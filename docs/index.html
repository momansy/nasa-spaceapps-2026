01 / Understand

What is the NASA challenge?

The official challenge is called Space Mission Design Game. Design an interactive educational game where players experience the engineering decisions behind a real space mission.

Official requirement, simplified: Players must design and manage a mission, balance competing constraints, and see how their choices influence mission success. NASA does not mandate that we use Unity, React, a 3D engine, or a specific spacecraft.
THE SCIENCE

Choose a real objective

What should the mission learn? Example: observing Earth's oceans, atmosphere, forests, or other targets. The objective determines the instruments and orbit.

THE ENGINEERING

Balance limited resources

A better camera improves science but may add mass, price, power use, and data. The design has to work as a complete system, not just as individual parts.

THE LEARNING

Explain consequences

Show why the satellite fails or succeeds. A meaningful warning such as “insufficient downlink” teaches more than a simple red error message.

02 / Our direction

The proposed idea: MissionForge

A strategy game where you design an Earth-observation CubeSat, launch it, run scientific operations, recover from problems, and learn from a mission report.

Important: MissionForge is our team's proposed concept, not an official NASA-provided game specification. The final game engine and feature scope remain team decisions.
01
Pick a mission

Choose what to observe and define scientific success—for example, collecting a required number of usable Earth images.

02
Build the spacecraft

Select the camera, solar panels, battery, onboard storage, communications and launch arrangement.

03
Review trade-offs

Mass, energy, budget, data creation and downlink must satisfy requirements simultaneously.

04
Operate the mission

Experience simulated sunlight, eclipse, observations, data accumulation and ground contacts.

05
Face meaningful failures

Low energy? Storage full? No communication window? The player decides whether to adjust the design or mission plan.

06
Get a detailed debrief

See science collected, efficiency, mission constraints, failures, and recommendations for a better design.

Must-have

One complete playable mission, component selection, tested calculations, consequences, scoring and a shareable demo.

Nice-to-have

3D visuals, random events, multiple mission objectives, saving designs, educational tooltips and mission reports.

Not needed at first

Real launch physics, real-time multiplayer, an expensive game backend, an AI chatbot, or every planet in the Solar System.

04 / Team infrastructure

How do our AI agents talk?

Your coding agent runs on your own computer. GitHub is the shared inbox and source-code workspace. The Agent Mesh worker checks its inbox and can pass structured tasks to other online agents.

Codex workerTeammate A
↔
◈ GitHub IssuesShared task queue
↔
Claude workerTeammate B

The mesh.py worker registers itself, updates a heartbeat, reads assigned Issues and posts results. A separate coordinator can reassign certain queued tasks when someone goes offline.

DISCOVERY

Automatic presence

The live roster is determined by GitHub heartbeat Issues. No manual roster editing when someone joins or leaves.

COMMUNICATION

Handoffs & replies

A worker receives a task, processes it with Codex/Claude, and posts a result. Agents can send bounded follow-up tasks to others.

SAFETY

Human-protected code

Start in planning-only mode. No autonomous merges, deployments or account changes. GitHub Issues are not an exactly-once task queue.

New: automatic internet reconnection. Teammate onboarding now launches a local mesh_supervisor.py that restarts exited workers with 5–60 second retry delays. When internet returns, they can register a fresh GitHub heartbeat automatically. Read the reconnect guide ↗. This does not start a powered-off laptop or automatically replay interrupted running tasks.
Critical distinction: GitHub stores coordination messages; it does not keep your coding agent alive. Each worker must stay running on an active computer or server. If your laptop sleeps, the agent is offline. Multi-agent communication is not verified yet merely because the scripts exist.
05 / Dynamic teams

Two online or six online. Same network.

The competition team may have up to six human members. Our agent infrastructure does not require all six to be present. Each participant uses their own GitHub account and agent identity.

Illustrate active workers:

This is a demonstration of scaling—not a live GitHub status page or a list of your teammates' actual IDs.

Capabilities are flexible

Possible skills: simulation, frontend, UI/UX, research, scientific validation, 3D assets, testing and integration. An agent can have several capabilities. The coordinator routes tasks to suitable online workers.

Safe collaboration rules

One worker process per agent ID. Keep separate branches for implementation tasks, use pull requests for reviews, never auto-merge untested changes, and do not give agents shared personal credentials.

10 / Troubleshooting
If something fails, start here.
These issues are normal during first-time setup. Your agent should resolve safe environment problems and ask you only when an account, operating-system, or payment approval is genuinely required.




GitHub says 404 or “repository not found”.
The repository is private. Check that you're signed into your own invited GitHub account, accept the collaborator invitation, and confirm that gh api repos/momansy/nasa-spaceapps-2026 works. A 404 may simply indicate missing access. Do not use someone else's token.


Codex or Claude cannot authenticate.
Have the teammate finish the provider's own browser/device login. Then verify CLI authentication from a fresh shell. Never send provider cookies or credentials to GitHub Issues or chat messages.


It says “gh”, “git”, “python”, “codex” or “claude” not recognized.
Check whether installation finished and whether PATH has refreshed. Open a new terminal after WinGet installation if necessary. Check the executable path before installing a duplicate copy.


The agent looks installed but shows OFFLINE.
The worker must still be alive. Keep its own terminal running, inspect output/errors and verify the GitHub permission needed to create/update Issue records. Then check python mesh.py roster and status from a separate shell.


Only one agent is online; can we test?
Yes: verify that worker's own heartbeat and process. But do not claim a multi-agent exchange until a second actual worker is online and handles a harmless GitHub Issue.


Why do tasks stop when I close my laptop?
The worker runs locally, not on GitHub's servers. To remain available while laptops are off, the team must separately configure an always-on host for workers. An optional coordinator does not keep individual worker processes alive.


What if two agents use the same ID?
That can cause racing or duplicate work because GitHub Issues do not provide an atomic task claim lock. Use a separate personal GitHub login/unique ID and exactly one running worker for each ID.


Do we need Unity, Higgsfield, or Playwright immediately?
No. Basic connectivity requires Git, GitHub CLI, Python, and one Codex/Claude CLI. Unity is only for the Unity engine path; Higgsfield can cost credits; Playwright is for later UI testing.


The repository already exists on my computer.
The bootstrap scripts are designed to use a safe fast-forward pull rather than deleting files. If Git reports local changes or divergent history, stop and preserve that work; do not force-reset to get the setup running.

What counts as a credible model?
Every numeric rule should state units, constraints and origin. Example: solar power is consumed during operations, battery energy is finite, and downlink limits data returned to Earth. Explicitly label simplified or fictional values.
What data are we still waiting for?
No unpublished NASA dataset is identified as a mandatory blocker for this challenge. We can assemble a small cited component catalog from released references; extra announcements can still occur during the event.

13 / Questions and glossary
Everything you may be wondering.
No assumptions about prior programming, space engineering or AI-tool experience.




What is a CubeSat?
A small standardized class of spacecraft often used for research, demonstrations and education. We propose a CubeSat-scale Earth observation mission because its systems are easier to understand and simulate than a giant interplanetary mission.


What is “payload”?
The equipment that performs the mission's science, such as a camera or sensor. Payload choices affect spacecraft mass, energy demand, data and cost.


Why are batteries and solar panels relevant?
Solar panels generate electricity when illuminated; batteries supply energy when generation is insufficient, such as during orbital eclipse. A mission that consumes energy too quickly cannot operate reliably.


What is “downlink”?
Transmission of recorded information from spacecraft to Earth. Instruments can generate more data than can be downloaded, so communications and storage become engineering constraints.


What is an orbit and why does it matter?
The spacecraft's path around a planet. Orbit influences coverage, repeat observations, sunlight exposure, ground contacts and mission duration.


What is GitHub?
A platform for storing source code and coordinating work. Here we also use GitHub Issues as a mailbox for agent tasks and GitHub pull requests to review source changes.


What is a coding agent?
An AI assistant with access to authorized developer tools. Codex CLI and Claude Code can inspect project files, suggest plans and execute approved commands. Your account and machine permissions still control what they can actually do.


What is MCP?
Model Context Protocol: a standardized connection between AI assistants and external tools. Unity MCP is useful for Unity Editor; Playwright MCP for browsers; Higgsfield integrations for media. None is mandatory to get the core GitHub Agent Mesh connected.


Will my agent be able to work automatically?
Once its worker is running, it can poll GitHub Issues and process assigned tasks according to its configured mode and permissions. Initially we're limiting workers to planning-only mode. Fully unattended coding requires additional isolation, task locking, budget limits and safety review.


Does the private repository have a public website?
Not automatically. The website source is stored in the private GitHub repository under docs/index.html. An owner must enable and configure GitHub Pages on an eligible plan, or deploy the static docs folder to a hosting provider. Do not assume private-source access makes a public site secure.


Do I need to pay for anything?
Git, Python and GitHub CLI are free. AI provider access depends on each user's plan/account. Higgsfield generations can consume paid credits. Never let an onboarding agent purchase subscriptions or spend credits without approval.


What should I do right now?
Read the challenge overview, accept the private GitHub invitation, copy the agent prompt into your local Codex or Claude Code, complete your own account approvals, and ask the agent for proof of an ONLINE heartbeat. That's all you need for the initial setup.
